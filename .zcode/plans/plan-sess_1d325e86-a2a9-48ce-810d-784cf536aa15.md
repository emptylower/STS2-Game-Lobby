# Pure LAN Mode Picker Fix Plan

**Goal:** 修复 issue #40 剩余问题：从纯 LAN 入口可靠创建标准、每日挑战或自定义模式房间，且一次选择只启动一个 ENet Host，不触发或覆盖原生 Steam Host。

**Chosen design:** 保留原生 `标准/每日/自定义` Steam 建房按钮；现有 `LAN 调试建房` 点击后打开三选一 `PopupMenu`。菜单同步原生按钮的解锁状态，选择后直接把明确的 `GameMode` 交给现有 `LanConnectHostFlow.StartLanHostAsync`。

**Why this approach:**
- 比“多个 LAN 按钮”更少占用原生主机页面空间。
- 比“替换原生按钮”更安全，不改变 Steam 建房语义。
- 选择器与网络启动分离，能够在不真实监听 UDP 的情况下验证模式映射和单次回调。

**Out of scope:** 不修改续局通道绑定、身份码、大厅中继、端口常量、存档保护或发布流程；不直接更新 GitHub issue、测试 Release 或正式包。

## Task 6: Manual Reproduction and Cross-Mode Verification

使用新构建完整重启三端后验证，记录每段测试的大致时间：

1. **纯 LAN 自定义模式主路径**
   - 房主：多人 → Host → `LAN 调试建房` → `自定义模式`。
   - 预期房主日志有 `start LAN host gameMode=custom`、`LAN ENet host started`、`registered host origin channel=lan`。
   - 预期该段日志没有 `[SteamHost] Initializing Steam host`，也没有紧随其后的 `Stopping host. Reason: Quit` / `cleared host origin channel=lan`。
   - PC 与 Android 加入者输入房主 IP/端口，预期均收到 `Mode=Custom State=InLobby` 并成功进入自定义设置页。

2. **自定义开局与续局**
   - 三端完成自定义设置并开局，产生多人存档后正常退出并完整重启。
   - 房主安全载入；纯 LAN 存档仍出现 `effectiveHostChannel=lan` / `decision=skip_lan_origin`，不发布大厅房间。
   - 两个加入者使用持久身份或各自续局码重新加入，预期收到 `Mode=Custom State=InLoadedLobby`。

3. **标准与每日挑战回归**
   - 从同一 LAN picker 分别创建 Standard 和已解锁的 Daily，确认加入端收到相应 `Mode`，且没有 Steam Host/ENet Host 竞争。
   - 未解锁 Daily/Custom 的存档环境中，对应 picker 项为 disabled，不能通过手工信号绕过。

4. **原生与大厅路径不回归**
   - 点击原生 `自定义模式` 按钮仍走游戏原生 Steam Host，LAN picker 不自动打开。
   - 游戏大厅创建 Custom 房间仍可通过中继加入；继续局仍自动恢复大厅房间。

5. 若任何设备失败，收集房主 PC、加入 PC、Android 三份新的 `godot.log`，按上述时间点对齐 `host_flow`、`SteamHost`、`ENetHost`、`lan_direct_join` 与 `InitialGameInfoMessage`。

## Completion Criteria

- LAN picker 提供且只提供 Standard/Daily/Custom 三项，并尊重原生解锁状态。

- 原生 Steam 建房和游戏大厅三种模式行为保持不变。
