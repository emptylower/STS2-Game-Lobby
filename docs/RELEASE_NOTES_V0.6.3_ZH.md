# STS2 LAN Connect v0.6.3 正式版发布说明

- 日期：2026-09-23
- 版本：客户端 MOD 与 lobby-service 均为 `0.6.3`。
- 分发：GitHub 正式 Release（非预发布）。本次不更新 Steam 创意工坊，工坊条目「游戏大厅」仍为 `0.6.2`。
- 本版汇总 `0.6.3-alpha.1`～`alpha.3` 的修复，行为实现与已实测的 `alpha.3` 候选一致。

## 主要修复

### 1. SL / 读档后保持原房间协议

修复 `0.6.2` 的回归：原先用新协议创建的多人房间，在 SL 或保存退出后重新载入时，可能被按“兼容旧版 Mod”创建；安装 RitsuLib 的玩家会因此被拒绝续局。

原流程在存档绑定缺失或协议字段不完整时，把协议选择视为空值，随后建房保护逻辑冻结为兼容协议；错误选择还可能写回续局绑定。本版在原生载入、快速载入、建房、大厅恢复发布及保存路径验证原协议。无法确认时在建房前停止并提示恢复配置；保存事件、延迟保存及“重开一局”都使用原房间冻结的协议。确实来自早期 schema 0/1 的兼容协议记录仍可恢复。

配置保存改用同目录临时文件替换，并保留上一份有效的 `config.json.backup`。主配置损坏时尝试恢复备份并保留损坏副本；两份都不可读时进入只读保护，阻止建房和配置写入，仍可查看提示与导出诊断。

### 2. 兼容协议房间可加入、可正常开局

- 修复 `0.6.2` 加入兼容房间时错误要求 `hostNativeBusTypeId`、立即以 `lan_type_id_mismatch` 拒绝的问题。该字段仅在新协议房间校验。
- 修复桌面房主使用兼容协议开局时，JIT 内联绕过位宽补丁，导致客机解码错误、房主黑屏等待的问题。桌面端在消息总线边界显式写出正确的玩家列表位宽；新协议与 Android 原有序列化路径保持不变。

### 3. 昵称与预检弹窗

- 加入后补发昵称同步，减少新协议房主偶尔显示为原版回退名 “Test Host” 的情况。
- 加入前 MOD 预检弹窗跟随大厅主题；只剩取消动作时不再显示两个取消按钮。

## 已受影响存档如何处理

更新前先备份游戏存档和 `user://sts2_lan_connect/`。若提示无法确认原房间协议，请检查有效配置备份中的 `saveRoomBindings`，或导出诊断后联系开发者核实。

不要改选兼容协议、关闭 RitsuLib 后强行续局，或反复保存来绕过提示。保护措施能阻止新的错误写入，但不能自动还原已被 `0.6.2` 覆盖且没有备份的原协议记录。如果启动时提示联机补丁安装失败，请先解决模组冲突并完整重启，再载入多人存档。

## 升级与服务端

- **客户端需要更新**：同房玩家统一使用 `0.6.3`，覆盖安装后完整重启游戏。客户端包：`sts2_lan_connect-release.zip`。
- **本次存档修复不要求更新服务端**：lobby-service 相对 `0.6.2` 仅同步版本号；现有 `0.6.2` 服务端可继续使用。仍运行 `0.6.1` 或更早版本的服务端，需要具备 `0.6.2` 引入的消息 ID 透传能力才能支持当前新协议客户端。
- wire 协议不变，tail 房间的 `minimumClientVersion` 保持 `0.6.2-alpha.1`。
- 本 Release 附带 `sts2_lobby_service.zip`，且为正式版本；已启用自动更新的节点可能安装 `0.6.3` 并重启。服务重启会清空内存中的房间连接，请按现有运维策略安排。
- 工坊尚未更新，订阅工坊本次不会自动获得客户端修复；请从 GitHub Release 获取客户端包。

## 实机验证与范围

测试使用 `0.6.3-alpha.3` 候选，Mac 端由 Steam 启动，Android 端运行于 Android Studio AVD（API 35、arm64）；两端游戏均为 `0.111.0`，服务器为客户端默认测试服“魔仙堡”。Android 是模拟器测试，本轮没有覆盖 Android 实体手机或 Windows 房主。

| 场景 | 兼容协议 | 新协议 + RitsuLib 0.5.13 |
|---|---|---|
| 双端加入并击败第一个怪物 | 通过 | 断线恢复后通过 |
| 房间管理“重开一局”（SL）并重新加入 | 通过 | 通过；补测自动重试后成功 |
| SL 后进入下一战斗房间并继续同步操作 | 通过 | 首次被丢包打断；独立补测通过 |
| 保存退出、官方多人读档、重新加入并同步操作 | 通过 | 通过 |
| 续局绑定保持原协议 | `compat_4_5_v1 / none` | `tail_v1 / native_bus_v1`，未降级 |

第二战验证到双端继续出牌同步，没有打到第二战胜利。测试证明本次协议回退回归已修复；尚未使用受影响玩家的原始存档验证其数据能否恢复，也未逐一复测第三方快速存档 MOD。

## 已知问题（本版未修复）

1. **两次严重丢包后断线**：新协议测试分别在第一战和首次 SL 后第二战发生 `UnknownNetworkError`。大厅 HTTP 仍可达；具体中继、UDP/NAT 或端点原因尚未确定，需要服务端中继日志进一步分析。
2. **候选连接切换可能误报 `ModMismatch`**：SL 补测中，首次候选超时后切换地址，出现扩展握手缺失并显示模组不匹配；下一轮自动重试成功。日志与代码路径指向握手绑定在候选切换时未重新建立，但该原因尚未经故障注入验证。本版没有包含这一问题的修复。
3. 兼容协议测试曾有一次探测失败，重试成功；SL 过渡时还记录到 `Peer not connected` 与网络提示控件异常。

**核心回归功能通过，整体验收仍有未解决项；本版不是全程无异常运行的验收结果。** 遇到上述问题时请保留两端完整日志和诊断，提交前去除密码、token 及其他个人信息。
