## P1：可信离开事件与名册生命周期

基线中的最小场景是三人准备房：房主与两名客机已建立 Tail 名册，其中一名客机退出后，原生名单已经减员，剩余客机的 Tail baseline 却仍含退出者。下一次开局按 `StateTransition` 校验，会拒绝成员变化。

本轮保留 wire codec 的 **2～8 人**约束。目标包括 3→2、8→7，以及连续减员后仍有至少两人的场景。**2→1 不在修复覆盖范围内**：最后一名客机离开后，自动退成单人并继续开局仍保持 fail-closed，不生成或接受一人 Tail 快照。因此不能将本轮结果表述为“所有减员场景均已修复”。

最终机制保持以下不变量：

1. 只接受当前权威房主、正确接收通道和对应准备阶段的原生 `PlayerLeft` 事件。非法来源、房主自身离开、无关会话或未知成员不能获得减员授权。
2. 将可信离开记录到认证 departure ledger，仅在后续 `MembershipMutation`／`StateTransition` 中兑现。`CurrentState` 仍要求既有快照逐字节重复，不因为有待处理离开记录而放宽。不得通过通用 `Reset()` 重新建立 baseline，也不能由任意全量快照自行决定谁已离开。
3. 房主记录逻辑名册变化为 dirty，在下一次权威全量提交时合并成员变化并提交对应版本。连续多次离开可以合并，不能让每个客户端按每条原生事件自行增加版本号。
4. 接收下一张快照时，仍校验房主、成员／槽位、权威版本、原生 body 及影子数据。成功通过完整验证后才提交新状态并消费对应 ledger；坏 body、重放或其它拒绝不能提前改变 baseline 或消耗待处理记录。
5. 处理离开后替补加入、复用同一槽位及同一玩家重新加入，避免旧离开记录误伤新成员。成功提交、会话关闭和阶段切换按绑定生命周期收场，旧准备阶段的授权不能泄漏到下一阶段。
6. 运行中的断线角色仍属于本局玩家集合，不能套用准备房减员规则；本轮也不因此解除或改写存档绑定。

相关实现边界为 [Tail Runtime](../../sts2-lan-connect/Scripts/Protocol/Patches/LanConnectTailMessageRuntime.cs) 与 [Roster Authority](../../sts2-lan-connect/Scripts/Protocol/LanConnectRosterAuthorityState.cs)。本轮不新增 wire 消息类型或字段；是否与旧客户端所有组合互通，必须由实际组合测试确认。

## P1：续局发送名单归一化

例如存档顺序为 `[房主, A, B]`，实际加入为 `[房主, B, A]`。基线原生 body 使用加入顺序，Tail 使用存档 `RealSlotId` 顺序，因此相同成员集合也会被严格比较拒绝。

修复发送入口生成新的 `playersAlreadyConnected` 列表，按 Tail 已确认的存档槽位投影排列；原始列表内容、顺序和对象归属不变。`isReady`、`isModded` 等原生字段随玩家身份一起保留，不能在重建列表时丢失。原生列表计数仍按其 8 位计数格式处理，确保完整八人名单可以往返，不把其它消息的扩展列表位宽套到此字段。

接收端继续拒绝重复、缺失、非存档玩家、错误槽位、影子载荷不一致和错误位长度。不能仅把 `SequenceEqual` 换成宽松的集合比较；旧房主若仍发送不规范 body，也不能在未验证身份与字段对应的情况下直接接受。

## P2：新旧容量构造函数

由 [构造兼容解析器](../../sts2-lan-connect/Scripts/LanConnectStartRunLobbyConstructorCompatibility.cs) 精确匹配：

1. 新版：`(GameMode, bool isCustom, INetGameService, IStartRunLobbyListener, int maxPlayers)`。
2. 旧版回退：`(GameMode, INetGameService, IStartRunLobbyListener, int maxPlayers)`。

使用完整参数类型序列，不允许反射默认绑定器通过 `int → long` 或接口到 `object` 等转换误选其它重载。既有生产 postfix 按 `netService` 名称注入，新增 `bool` 不应造成参数错位；两个加入入口的容量同步补偿继续保留。

基线原生构造函数的容量参数只写入标量，加入前还有补偿，因此构造钩子被跳过不能单独证明八人功能已经失效。本轮应修复已确认的目标解析遗漏，并补第 5／8 人、满员拒绝和每日模式的验收。
