## 修复范围

### 桌面兼容协议的加入响应

前轮遗漏了 `compat_4_5_v1` 桌面房主的手写加入响应布局。0.113 在 `seed` 之后增加 `gameMode`、`isCustom`，旧实现直接写入 `ascension`，可使后续字段静默错位。

本轮按实际运行时字段形状写入新增字段；旧版没有这两个字段时保持旧布局，不以新版字段的直接引用破坏旧版加载。消息总线强制写入的协议门禁保持不变。

### 极速与恐惧模式

- 大厅及 LAN 模式选择支持当前游戏存在的极速／恐惧模式，进入对应原生准备页，并沿用现有最大人数参数。
- 复用游戏原生解锁状态；未解锁不可选择，旧版不存在这些模式时不提供选项。
- 房间卡片和详情显示“极速／恐惧”，不再落入 `STD`。

本轮不强制解锁模式，不修改进度；未将第三方补丁的局中重开、结算页新开一局等额外功能纳入修复范围。

### 手机点按卡牌预览

用户确认手机能看到卡牌文字，但点按无法预览。本轮修复触摸、模拟鼠标及悬停事件之间的预览关闭和固定状态冲突：

- 轻触释放时激活预览；拖动、取消及多指手势不触发。
- 对同次触摸产生的模拟鼠标和 `MetaClicked` 激活去重。
- 已固定的预览不再被普通悬停或悬停结束事件关闭。

手机手势的 6 项纯单元回归已通过，包含在最终主测试集中；另补充 3 项 GdUnit 场景，但尚未执行。Android 实机仍需回测，不能将模拟事件结果等同于手机验收。

## 安装与启动检查

最终修复包已安装至本机游戏并刷新 macOS 签名，安装使用 `--no-save-sync`，未迁移存档。包内、交付目录及已安装 DLL 的哈希一致。

本轮使用 `--force-steam=off` 进行单实例无界面启动检查。首轮 `/tmp/sts2-round2-runtime.log` 证实初始化成功，但限时退出发生在菜单资源预载阶段；随后延长验证，最终日志 `/tmp/sts2-round2-runtime-menu.log` 证实：

- 已跳过 Steam 初始化，加载构建标识为 `0.6.3+compat.2` 的 MOD。
- 11 个初始化阶段成功，补丁组 `applied=10, failed=0`，大厅运行时 ready。
- 中文回退字形可用，在 12,375 ms 到达主菜单。
- 限时进程正常退出，退出码为 0，结束后无残留游戏进程。

菜单后的 Common 资源预载阶段出现 Godot `worker_thread_pool`／`ScriptManagerBridge` 的 `Invalid Task ID` 提示；另有退出时 RID／资源未释放提示。进程退出码为 0，未见 MOD 异常堆栈证据，但本轮未证明这些引擎提示已解决，不宣称整份日志零错误。先前未加载 MOD 的日志中也有同类 `Invalid Task ID`，仅作为历史对照，不据此推断全部错误原因。此次启动检查不代替建房、加入或手机预览的界面验收。

构建、测试和游戏验证串行执行，同一时间仅运行一个游戏实例。当前环境禁止自动操作游戏界面，不绕过此限制。
