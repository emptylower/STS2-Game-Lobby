# STS2 LAN Connect v0.6.3-alpha.3 本地候选版说明

- 日期：2026-09-23
- 版本：客户端 MOD 与 lobby-service 均为 `0.6.3-alpha.3`；修复在客户端，服务端仅同步版本号。
- 这是本地候选包，尚未发布到 GitHub Release 或 Steam 创意工坊；当前正式版仍为 `0.6.2`。

## 修复：多人续局的房间协议可能被改成旧协议

`0.6.2` 恢复多人存档时，客户端从独立的 `user://sts2_lan_connect/config.json` 查找原房间协议。原有流程在绑定缺失或协议字段不完整时，把协议选择当成空值；随后原生建房保护逻辑自动冻结为“兼容旧版 Mod”。没有 RitsuLib 时，这种错误协议还能被发布和回写，进一步污染续局绑定；有 RitsuLib 时会被旧协议门禁拒绝。

本版在原生载入按钮、快速载入、建房、大厅恢复发布及存档写入路径验证原协议。无法确认时在游戏建房前停止续局并提示恢复配置，不再猜测为旧协议。确实由早期 schema 0/1 保存的旧协议房间仍可恢复。保存事件及“重开一局”写回绑定时，使用房间当时冻结的协议选择。

配置写入改为同目录临时文件替换，并保留上一份有效的 `config.json.backup`。主配置损坏时尝试恢复备份，保留损坏副本；两份都无法读取时，进入只读保护状态并阻止建房与配置写入，让用户仍能查看提示和导出诊断。

## 已受影响存档的处理

若恢复时提示原房间协议无法确认，请先备份游戏存档和 `user://sts2_lan_connect/` 目录。检查 `config.json.backup` 是否含该存档原来的 `saveRoomBindings`。不要改选“兼容旧版 Mod”、关闭 RitsuLib 后续局，或继续保存来绕过提示。没有可用绑定时请导出诊断报告，并联系开发者根据原房间记录核实协议；客户端无法从游戏存档安全推断原协议。

该保护可以阻止新的错误续局写入，但无法自动还原 `0.6.2` 已覆盖且没有备份的协议记录。
如果启动时提示联机补丁安装失败，请不要继续载入多人存档；保存诊断报告并在解决模组冲突后完整重启游戏。

## 兼容性

- wire 协议不变；tail 房间的 `minimumClientVersion` 仍为 `0.6.2-alpha.1`。
- 服务端功能未变，现有兼容服务端无需为此问题升级。
- 更新客户端后请完整重启游戏；联机时双方使用一致的客户端版本。
